# ADR 0002：设计基线与技术基线的对齐

状态：已采纳（2026-10-16，开发计划 M0）。

## 背景

`docs/design/v0.44/完整设计执行基线_v0.44.md` §4.1 与 §5.3 仍写有“Unity引擎家族、.NET服务端、首轮仅Windows 64位客户端”，与 [ADR 0001](0001-technical-baseline.md)（Godot 4＋类型化GDScript、Go服务端、Windows/macOS/iOS/Android四端必需）冲突。此外，闭环文档对原型测试世界是否重置写的是“另行确定”。

## 决定

1. **引擎、语言、平台以ADR 0001为准。** 基线§4.1中与引擎无关的规则照常执行：服务端权威范围、每次写入带request_id且幂等、物品位置由条件更新加行锁保证、资金非负、跨区所有权令牌与单一激活租约、同号全局单角色在场。§5.3所附Unity专用服务器链接不适用；PostgreSQL锁说明继续作为参考。
2. **历史快照不改写。** `docs/design/v0.44/`保持导入原文，SHA仍由`docs/import-manifest.json`校验。冲突只在本ADR说明。
3. **测试世界可按公开轮次重置**（基线§4.2）。重置前须导出该轮验收证据；这与正式世界不常规清档的原则互不混淆。
4. **运行数据权威源为`shared/data/`。** 其中由`docs/design/v0.44/*.json`派生的文件由`scripts/export_data.py`生成，CI用`--check`检查是否偏离源文件；只写在Markdown里的参数由人工维护在`items.json`和`world.json`中，并在文件内注明来源章节。
5. **移动端操作方案仍未设计。** 基线§3.1只定义了键鼠操作，四端交付需要的触屏方案是待用户确认的开放项（开发计划Q1），本ADR不代为决定。

## 后果

服务端测试直接读取`shared/data`和设计文档中的JSON夹具，与Python演算对照；数值调整必须改源文件、重新导出，并让对照测试保持通过或同步更新。
