# M3 · 世界、移动与地图灰盒 验证记录

日期：2026-10-16。范围：开发计划M3。**这不是游戏验收**：还没有战斗、物品和任务，16项可玩验收仍全部待执行。M3覆盖第15项“区域权限”中的移动部分；攻击权限要到M4有了战斗才能验证。

## 用户决定（开放问题Q1）

选择方案1：M3–M8只做PC操作；手机端保证能启动、能连服、点地面能移动；完整的触屏方案在G2之前单独设计。

## 偏离原计划之处

原计划为“每个区块一个线程，跨区块时走租约交接”。实际改为**一个权威世界循环（20Hz）统管六个区块**，角色属于哪个区块由位置直接算出。理由：

- “角色同一时刻只属于一个区块”在这种结构下天然成立，不需要交接机制，也就不存在交接失败的情况。
- 拆成多个线程或进程是应对负载的扩展手段，应等G2压测证明需要时再做。
- 原计划中“由Godot工具从灰盒场景导出导航数据”也做了简化：改为`shared/data/map.json`作为唯一的地图数据源，服务端用它寻路，进入世界时把地图发给客户端，客户端据此生成灰盒。这样不需要导出工具，也就不会出现两份数据不一致。

## 产物

- 数据：`shared/data/map.json`，包含六个区块、七条道路（其中一条风险捷径）、风险区、障碍物、出生点，以及移动参数。加载时与`world.json`交叉校验。
- 服务端：
  - `internal/world`：1米网格A*寻路，禁止斜穿墙角，路径沿视线拉直；固定20Hz的世界循环；每秒10次快照，视野80米。
  - 网关新增`move_to`、`stop`两种消息和`snapshot`推送。
  - 迁移`0003_position.sql`：保存角色离开世界时的位置。
- 客户端：
  - `SnapshotBuffer`：延迟100毫秒插值，不外推。
  - `MapBuilder`：根据地图生成灰盒场景。
  - `CameraRig`：斜俯视镜头，缩放限制在12–60米，中键拖动旋转，Home键复位。
  - 世界画面`world_view.tscn`：右键或点按地面移动，S键停止，风险区确认弹窗，HUD显示所在区域。
  - 账号界面同时作为外壳：进入江湖后显示世界画面，被踢下线时退回菜单，断线重连后重新接管角色。
- 导出：`client/export_presets.cfg`（四个平台）；`.github/workflows/export.yml`（在CI导出Windows、macOS、Android）。

## 测试证据

本机PostgreSQL 16.15（临时实例），Go 1.25.6，Godot 4.7.2 macOS。

| 测试 | 结论 |
|---|---|
| `world.TestRouteThroughBlocks` | 用模拟时钟按A→C→A→E→A→B走完五段。每段经过的区域依次是“起点区块→道路→目标区块”；每个tick的位移不超过4米/秒×0.05秒；全程都在可行走区域；用时等于路径长度÷4米/秒（误差在两个tick以内） |
| `world.TestOrdinaryRouteIgnoresShorterRiskShortcut` | 从河湾镇北侧去F区西南角，走风险捷径比普通路线短约50米；未确认时仍经B区绕行，全程不进入风险区 |
| `world.TestRiskAreaNeedsConfirmation`、`TestRiskShortcutOnlyWithConfirmation` | 目标在风险区或捷径上时，未确认会被拒绝；确认后可以进入；已在风险区内的角色离开不需要确认 |
| `world.TestPathAvoidsObstacles` | 路径绕开建筑，每段都无遮挡；目标在建筑内、地图外、空地上时均判为无法到达 |
| `world.TestMoveRequestsAreRateLimitedAndCannotSpeedUp` | 1秒内发100次移动请求：只接受10次；位移不超过4米 |
| `world.TestSpawnDetachAndSnapshots` | 保存的位置已不可行走时回到出生点；旧连接不能停止已被新连接接管的角色；只有在线的角色收到快照；视野之外的角色看不到 |
| `ws.TestMoveAndSnapshots` | 真实连接：未进入世界时移动被拒；缺少坐标被拒；目标在建筑内回`unreachable`，在风险区回`risk_confirmation_required`；走4米实际用时不少于0.9秒；快照显示到达；`stop`能让角色停下 |
| `ws.TestPositionIsSavedOnLeave` | 离开江湖后角色从世界中移除；再次进入时回到离开前的位置 |
| `ws.TestPlayersSeeEachOtherAndKickKeepsCharacter` | 两个账号互相可见；被踢后角色仍在世界中，新设备可以接管并移动；网络中断后角色保留到期离开，位置已保存 |
| `ws.TestRegisterRequestIDsAreScopedPerConnection` | 回归测试，对应下文的发现1 |
| Godot `test_world` | 插值（中点、不外推、忽略乱序、移除消失的角色）；地图节点；镜头缩放限制与复位；地面点击换算；风险确认弹窗；HUD；被踢后退回菜单 |
| Godot `smoke_ws`（连真实服务端） | 在原有流程中加入：进入世界时收到六区块地图；走3米并由快照确认到达；进入风险区时被要求确认。连续3次通过 |

变异检查（逐项故意改坏，确认测试会失败，改完后恢复）：

| 改动 | 结果 |
|---|---|
| 移动速度翻倍 | 三个测试失败 |
| 取消请求频率限制 | 测试失败 |
| 拉直路径时不检查障碍 | 两个测试失败 |
| 风险区不需要确认 | 起初**没有**被发现：原测试中普通路线本来就更短。补上“风险捷径更近”的场景后，测试失败 |

## 人工视觉检查

用`tests/capture_world.gd`在1280×800窗口中真实渲染并截图：账号界面、河湾镇、向西行走、拉远并旋转镜头、风险确认弹窗。结论：

- 区块颜色、建筑、道路、红色风险捷径都显示正常；HUD和弹窗中文显示正常；镜头跟随角色。
- **发现并修复**：3D文字（区块名、角色名）原先太小，糊成一团。改为固定屏幕尺寸并加黑色描边后，复查可以清楚看到“A 河湾镇”和“剑客271”。

导出时发现：Apple Silicon和移动端导出要求开启ETC2/ASTC纹理压缩，已在项目设置中开启。应用名也从“Jianghu — Bootstrap”改为“Jianghu”。

## 发现的问题

1. **注册请求编号全局冲突（M2遗留）。** 注册的去重编号原先是全局共享的：两个客户端只要用了相同的编号，后注册的人就会被拒绝，恶意客户端还能抢先占用编号。现已改为按连接区分，并补了回归测试（换回旧代码，测试会失败）。协议文档已同步更新。
2. 3D文字太小（见人工视觉检查）。

## 未验证与限制

- 没有做手机真机测试；`ws://`明文连接在iOS和Android上的表现未验证。
- 地图上的距离不代表设计中的运输时间（例如A到B普通路线设计为10分钟），运输时间由M5的物流班次参数决定。
- 位置只在离开世界和服务端关停时保存；服务端崩溃会丢失最近的位置（位置不是资产，可以接受）。
- 角色视作一个点，没有碰撞体积；角色之间可以重叠。
- 危险区的延迟离场要等M4的战斗计时一起实现。
- 世界画面没有做完整的人工交互验收（只有自动截图），也没有测量帧率。
