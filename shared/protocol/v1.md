# 实时协议 v1

服务端实现：`server/internal/transport/ws`；客户端实现：`client/scripts/net/`。两边的测试以本文为准，协议改动必须同时更新本文、服务端和客户端。

## 连接

- 地址：`ws://<主机>:<端口>/v1/ws`。只有服务端配置了数据库（`JIANGHU_DATABASE_URL`）时才开放。开发阶段用明文 `ws://`，只限本机或可信局域网；正式环境必须改用 `wss://`。
- 每条消息是一个 UTF-8 JSON 文本帧，单条不超过 64 KiB。二进制帧会被拒绝。
- 客户端连续 60 秒没有发送任何消息，服务端会断开连接。空闲时客户端应定期发 `ping`。

## 信封

所有消息都使用同一种外层结构：

```json
{"v": 1, "type": "login", "req_id": "c-17", "payload": {}}
```

| 字段 | 方向 | 规则 |
|---|---|---|
| `v` | 双向 | 协议版本，当前为 1。版本不符时，服务端回 `unsupported_version` 后断开（关闭码 4003） |
| `type` | 双向 | 消息类型 |
| `req_id` | 客户端→服务端，必填 | 1–64 个可打印 ASCII 字符。服务端的回复带回同一个值；服务端主动推送的消息没有此字段 |
| `seq` | 服务端→客户端 | 每个连接内从 1 开始严格递增 |
| `server_time` | 服务端→客户端 | 服务端时间，Unix 毫秒 |
| `payload` | 双向 | 消息内容（对象），可省略 |

成功的回复类型为 `<请求类型>.ok`；失败统一为 `error`：

```json
{"v":1,"type":"error","req_id":"c-17","seq":5,"server_time":1792140000000,
 "payload":{"code":"character_present","message":"...","detail":{"character_id":12}}}
```

## 幂等

会改变数据的请求（`register`、`char_create`）按 `req_id` 去重：用同一个 `req_id` 重发，返回第一次的结果，不会重复执行。同一个 `req_id` 换了内容会被拒绝（`bad_request`）。如果收到 `internal` 错误，可以用同一个 `req_id` 安全重试。`req_id` 的作用范围：`char_create` 按账号区分；`register` 按连接区分（登录前没有账号可以区分），这样不同客户端用了相同的 `req_id` 也不会冲突。注册成功后网络断开、重连再发，会收到 `name_taken`，此时直接登录即可。

## 消息

| 请求 | payload | 成功回复 payload | 可能的错误码 |
|---|---|---|---|
| `ping` | — | — | — |
| `register` | `{name, password}` | `{account_id}` | `invalid_name` `invalid_password` `name_taken` |
| `login` | `{name, password}` | `{account_id, token, expires_in}` | `bad_credentials` `already_authenticated` |
| `resume` | `{token}` | `{account_id}` | `bad_credentials` `already_authenticated` |
| `char_list` | — | `{characters:[{id,name}], present: null 或 {character_id, state}}` | `not_authenticated` |
| `char_create` | `{name}` | `{id, name}` | `invalid_name` `name_taken` `character_limit` `not_authenticated` |
| `enter_world` | `{character_id}` | `{character_id, name, x, z, area, zone, map}` | `unknown_character` `character_present` `not_authenticated` |
| `leave_world` | — | — | `not_in_world` `not_authenticated` |
| `move_to` | `{x, z, accept_risk?}` | `{path: [[x,z], ...]}` | `not_in_world` `unreachable` `risk_confirmation_required` `rate_limited` `bad_request` |
| `stop` | — | — | `not_in_world` |

校验规则：
- 名字：2–32 个字符，只能是字母（含中文）、数字、`_`、`-`。
- 密码：8–128 字节。
- 账号不存在、密码错误、令牌无效，三种情况返回完全相同的 `bad_credentials`，不暴露账号是否存在。同一连接累计失败 5 次后，服务端断开（关闭码 4002）。
- 令牌有效期 7 天，服务端只保存令牌的哈希。

通用错误码：`bad_request`（格式错误或 payload 不符）、`unknown_type`、`internal`（可重试）。

## 世界与移动

- 坐标单位为米：x 向东，z 向南，地面高度 y=0。`enter_world.ok` 带上服务端的地图（区块、道路、风险区、障碍物、步行速度），客户端据此绘制场景。地图的唯一数据源是 `shared/data/map.json`。
- `move_to` 只告诉服务端目标点。路径由服务端规划，按步行速度（4 米/秒）移动角色；客户端不能上报自己的位置或速度。回复中的 `path` 是规划好的路径点，第一个点是当前位置。
- 普通路线一律绕开风险区。如果目标在风险区内，或者只有经过风险区才能到达，服务端回 `risk_confirmation_required`。客户端提示玩家后，带 `accept_risk: true` 重发。角色已经在风险区内时，离开不需要再确认。
- 每个角色每秒最多 10 次 `move_to`，超出回 `rate_limited`。
- `area` 是角色当前所在的区块、道路或风险区编号；`zone` 是区域类型：`service`（安全区）、`pve`（野外，禁止非自愿PVP）、`risk`（风险区）。

## 服务端推送

| 类型 | 时机 | payload |
|---|---|---|
| `snapshot` | 角色在世界中时，每秒 10 次 | `{tick, entities: [{id, name, x, z, area, zone, moving}]}`：80 米视野内的所有角色（含自己）。客户端在两次快照之间插值显示，不做外推 |
| `kicked` | 同一账号在别处登录或用令牌恢复了会话 | `{reason: "logged_in_elsewhere"}`，随后断开（关闭码 4001） |

**以关闭码为准。** 服务端在关闭连接前发出的最后几条消息（`kicked`推送，以及断开前的`error`）只是尽力送达：消息和关闭帧在同一轮读取中到达时，Godot 的`WebSocketPeer`会丢掉前面的消息（已在 Godot 4.7.2 实测）。所以客户端必须根据关闭码判断断开原因，不能依赖关闭前的那条消息。

## 在场规则

依据基线§4.1，详见`docs/data/state-machines.md`§1。

- 一个账号同一时间只能有一个角色在世界里。如果另一个角色还在，`enter_world` 返回 `character_present`，`detail.character_id` 指出是哪个角色。
- 断线后，角色在安全区内保留 30 秒（`world.json combat.safe_zone_disconnect_seconds`）。这期间只能重连这个角色（`enter_world` 同一个 `character_id`），不能换角色。
- 被踢下线时，角色不会离开世界：新设备可以接管同一角色，但要换角色，必须先 `leave_world` 或等保留期结束。
- `leave_world` 在安全区立即生效。危险区的延迟离场在 M4 与战斗计时一起实现。
- 断线期间角色停在原地，不会自动行动；保留期结束后离开世界。离开时保存位置，下次进入从原地继续（原地已不可行走时，回到河湾镇出生点）。

## 关闭码

| 码 | 含义 |
|---|---|
| 1000 | 正常关闭 |
| 1001 | 服务器关闭（going away） |
| 4001 | 同一账号在别处登录 |
| 4002 | 登录失败次数过多 |
| 4003 | 协议版本不支持 |
| 4004 | 客户端读取太慢，发送队列已满 |

客户端收到 4001、4002、4003 时不应自动重连。其他情况可以按退避时间重连（0.5 秒起，每次翻倍，最长 30 秒），重连后用令牌发 `resume`。
